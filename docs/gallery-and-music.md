# Shared guest gallery and visitor-local music

## Deployment checklist

1. Apply `drizzle/migrations/0001_shared_guest_gallery.sql` **once** to the same Supabase project the invitation uses. Use the project's privileged SQL editor or the existing Drizzle migration runner. The migration is registered in `drizzle/migrations/meta/_journal.json`.
2. Deploy the updated `wedding-concierge` Edge Function, including `supabase/functions/_shared/wedding.ts` and `_shared/music.ts`. Set a valid `GEMINI_API_KEY` in backend secrets for free-form requests. Never expose it as a `VITE_` variable.
3. Deploy the updated application. Set public `VITE_SITE_URL` to the final HTTPS invitation origin before building, e.g. `https://your-invitation.example`, for absolute social-preview image URLs. Share-card metadata uses `/social-preview.jpg` when no origin is configured.
4. Verify photo uploads on two different devices, the full five-photo state, Hindi/Urdu chat, an unknown song request, and browser-blocked playback.

The implementation has been tested locally, including SQL permissions and limits in embedded PostgreSQL (PGlite). Production migrations, Supabase Realtime and real Gemini responses are **not** verified by those tests. This workspace has no privileged database migration connection or Gemini secret configured for deployment.

## What “five photos” means

- Five **additional shared guest photos total**, not five per device or five per upload. The original eight-photo gallery remains intact.
- Anyone can upload without signing in, until the five slots are full. Only a privileged site owner can remove a photo. This matches an open guest gallery, but it is **not moderated** or abuse-proof: an unwanted visitor could fill the slots. For a public, widely shared invitation, consider authentication or approval before publishing.
- Multiple uploads are processed sequentially; successes remain saved if a later file fails, and the UI reports partial success. The database serializes slot allocation and rejects a sixth image even when guests upload simultaneously.
- Input: JPEG/PNG/WebP, at most 10 MB, at most 40 megapixels after decode. The browser strips source metadata by re-encoding to JPEG at at most 1400 px on the longest edge. The server limits decoded JPEG data to 800,000 bytes and checks JPEG signatures. This is not face verification or full server-side image moderation.
- For this intentionally tiny gallery, compressed JPEGs are stored in a bounded table, not a Storage bucket. There are no orphan uploads or public Storage write/delete policies. The maximum total stored image payload is roughly 4 MB before base64 overhead.
- The client subscribes to insert/delete events and reloads on refocus. The migration adds the table to the standard `supabase_realtime` publication.
- If the migration is missing or the backend is unreachable, the UI shows an error with Retry and disables uploads. It never pretends a photo was saved locally.

### Owner removal

Use the privileged Supabase SQL editor or Table Editor to remove a specific slot after review:

```sql
-- Replace 3 with the slot you actually intend to remove.
DELETE FROM public.wedding_photos WHERE slot = 3;
```

This frees one slot for a new guest photo. Anonymous guests cannot delete or overwrite photos.

## Music

Six local tracks are available through the playlist:

1. Balagal Ula Bi Kamalihi — existing instrumental, now served as a smaller MP3.
2. Moonlit Dua — original soft ambient melody.
3. Rosewater — original warm plucked melody.
4. Royal Courtyard — original gentle bell-like melody.
5. Sufi Breeze — original meditative, Sufi-inspired instrumental.
6. Evening Mehfil — original relaxed, softly rhythmic instrumental.

The five new pieces are procedural synthesized compositions, generated by `scripts/generate-music.py`; no commercial recordings, artist voices or copyrighted samples were downloaded. They are **not sung qawwali performances**. Each new track is a 32-second looping miniature with a gentle fade at its boundaries. To regenerate, install `imageio-ffmpeg` in a Python environment and run the script. The prebuilt MP3 files are included; deployment does not need Python.

- Playback is local to the current visitor, not a remote control for all guests.
- Manual playlist selection, pause/resume, next track and volume work without Gemini.
- Exact common chat commands (“Play softer music”, “Play Rosewater”, “Pause the music”, “Change the song”) work instantly without a key. Other explicit mood/music requests go to Gemini.
- Both AI backends share a playlist instruction. Gemini can append a whitelisted playback marker. The client checks that the user asked about music, allows one recognized ID/action only, strips the marker, and dispatches a local event. Arbitrary URLs, code, unknown IDs and multiple actions are rejected.
- Unsupported songs are not fetched or downloaded. Simran should offer the available instrumentals instead.
- The same player is mounted on the homepage and `/ai-concierge`; the selected track is remembered locally. Playback itself does not continue uninterrupted across navigation.
- Audio is not preloaded or autoplayed on component mount. The invitation's explicit “Enter with music” gesture, the playlist or a chat request can start it. If a browser blocks playback, the panel opens with a Play button. The playing/paused indicator follows actual media events, not just the chat's claim.
- The original Balagal Ula verse text remains available under its track.
- `CUSTOM_MUSIC_URL` still overrides the first track. Only use a recording you have permission to publish.

## Other improvements

- One shared event source (`supabase/functions/_shared/wedding.ts`) for the invitation and both model backends.
- Lightweight WebP image variants used in the invitation. Original JPEGs remain available for customization. `scripts/optimize-images.py` regenerates variants and the share card using Pillow.
- Mobile keyboard/safe-area sizing, accessible controls and reduced-motion styling.
- Local tests cover database limits/permissions, file boundaries, music commands, player behavior, retry/clear controls, maps, and routing.
